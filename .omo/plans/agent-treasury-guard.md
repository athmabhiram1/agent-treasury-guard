# agent-treasury-guard - Work Plan

## TL;DR (For humans)

**What you'll get:** A Solana/Anchor program ("Agent Treasury Guard") holding an AI agent's operating budget in a PDA vault, spendable ONLY within a human-signed on-chain mandate (allowlisted payees, per-payee + per-tx caps, rolling budget, expiry, idempotency keys, kill switch, human co-approval for large spends) — plus a skippable stretch leg settling payouts over Token-2022 confidential transfers, demo CLI + minimal UI, clinic-grade TDD tests, and both submissions (Colosseum Crypto World's Fair + Adevar pre-audit sidetrack on Superteam Earn + tweet).
**Why this approach:** combinines approved picks #2 + #3 at their genuinely-open intersection (human payroll privacy TAKEN by Cloak Sep 28 2026; agent spend guards ALL EVM-off-chain). Core alone clears Adevar's complexity bar (allowlist-CPI x PDA x cap-math x roles) even if the CT stretch is cut. Enforcement lives in Anchor constraints + account state — safe even with the agent key fully stolen.
**What it will NOT do:** No off-chain guard server/plugin, no EVM code, no VM/DSL, no human-payroll UI, no multisig-relayer, no Merkle, no second product/chain/token.
**Effort:** Solo, 9 days to Oct 12 2026 (hard submission buffer 12:00 UTC — sidetracks may close morning PDT; exact minutes verified in Todo 1). Timebox: D1 spike+scaffold, D2-D3 core PDAs + 3 instructions, D4 approvals/kill/budget + self-audit, D5 stretch-or-cut decision + devnet, D6-D7 demo+docs+videos, D8 hygiene + submissions, D9 buffer. Non-code work capped at 2 days. Second cut (if behind at D5): drop frontend to CLI-only, phone-record videos.
**Risk:** CT leg is the schedule risk — isolated as skippable STRETCH with a 72h-before-deadline cut rule; core wins without it. Pitch clarity is the non-code risk (Colosseum weighs the ≤3-min pitch most).
**Decisions (locked):** Concept = mandate-bound idempotent disbursement vault core + CT stretch (approved); stack = Anchor + LiteSVM/bankrun + Vite React SPA + CI (Context7-decided, see Todo 15); tests = TDD for all code todos (user-chose), checklist-QA with artifacts for non-code todos; kill semantics = authority-only kill AND unkill (locked, no `if`); money values below are DEFAULTS the worker uses verbatim.

Account layouts (Anchor `#[account]`, 8-byte discriminator included; `INIT_SPACE` derived, no `realloc` ever):
- Treasury PDA `[b"treasury", authority]` — 99 B: authority(32) + kill_authority(32) + budget u64 + spent_window u64 + window_start_slot u64 + window_count u8 + killed bool + bump u8.
- Mandate PDA `[b"mandate", treasury, nonce:u64]` — 466 B: treasury(32) + nonce(8) + agent(32) + ct_mint(32, `Pubkey::default()` in core, bound to the team test mint ONLY in the Todo 12 stretch) + payees [Pubkey;8](256) + payee_count u8 + per_payee_spent [u64;8](64) + per_payee_cap + tx_ceiling + large_threshold + expiry_slot (u64s) + bump u8. Nonce enables mandate rotation without moving funds.
- SpendRecord PDA `[b"spent", mandate, idem_key:[u8;32]]` — 89 B: mandate(32) + idem_key(32) + amount + slot + bump. Created on every success; existence = replay.
- Approval PDA `[b"approval", mandate, idem_key]` — 81 B: mandate(32) + idem_key(32) + amount(8) + bump(1) + 8 discriminator. Single-use via Anchor-native `close = agent` ONLY — zero manual lamport or data handling in worker code (manual closes that skip data-zeroing enable revival attacks).

Instruction account contexts (signer/mut discipline):
- create_treasury: authority (Signer, mut, payer) → treasury (init) + system_program. Root of trust.
- sign_mandate: authority (Signer) + treasury (`has_one = authority`, seeds+bump verified) → mandate (init) + system_program. Agent key here = E03.
- agent_disburse: agent (Signer, must equal mandate.agent) + treasury (mut, seeds+bump verified) + mandate (mut, seeds+bump verified) + payee (mut SystemAccount, key must differ from treasury/mandate/record/approval keys) + spend_record (init, payer=agent, space=INIT_SPACE) + system_program. NO approval account here (amount > threshold is rejected E12 with route-to-large). Check ORDER (fail-fast, cheap first): (1) killed→E10, (2) slot < expiry→E08, (3) agent match→E03, (4) payee in allowlist→E05, (5) amount ≤ tx_ceiling→E07, (6) per-payee spent+amount ≤ cap→E06, (7) window rollover if slot-start > 1000 then budget/velocity→E11, (8) amount > large_threshold→E12, (9) init spend_record (replay→E09 by Anchor), (10) pinned System CPI signed via `new_with_signer` seeds `[b"treasury", authority, bump]`, (11) checked writes. ORDERING CAVEAT: Anchor `init` executes before the body, so a replayed key (E09) outranks later body checks when both apply — tests assert E09 in that overlap, killed-first holds otherwise.
- human_approve_large: authority (Signer, via treasury `has_one` + treasury seeds+bump verified) + mandate (seeds+bump verified) + approval (init, payer=authority, space=INIT_SPACE) + system_program. Creates approval binding (mandate, idem_key, exact amount).
- agent_disburse_large: agent (Signer, = mandate.agent) + treasury (mut) + mandate (mut) + payee (mut, same self-transfer guard) + spend_record (init, payer=agent) + approval (mut, seeds verified, `close = agent` UNCONDITIONAL — no conditional close exists in Anchor) + system_program. Requires approval.amount == disburse amount else E12; runs checks (1)-(7); closing refunds rent to agent.
- kill_switch: kill_authority (Signer, address == treasury.kill_authority) + treasury (mut). Kill AND unkill both here, both authority-only.

Error codes (verbatim in code + tests): E01 re-init, E02 payer-not-authority, E03 unauthorized, E04 nonce reuse, E05 payee-not-allowlisted, E06 per-payee-cap, E07 tx-ceiling, E08 expired, E09 replay, E10 killed, E11 budget/velocity, E12 approval-missing/consumed.

Security measures (process + code, worker-enforced):
- Constraint matrix: `init` never `init_if_needed`; stored bump + `bump = <target>` on every non-init PDA use (Anchor changelog rule); `has_one` on all authority relations; typed `Account<'info,T>` everywhere (discriminator = anti-cosplay); `seeds::program` default (own program).
- Math: `checked_*` on every amount/slot op + workspace `overflow-checks=true`; window rollover resets BOTH spent_window and per_payee_spent atomically in the same instruction.
- CPI: System Program ID pinned in code (never an account input); Token-2022 leg (stretch) uses `token_interface` with mint/program from the mandate-bound test mint only.
- Time: slots (PoH monotonic), never wall-clock; expiry/rollover constants from TL;DR defaults.
- CT stretch sequencing (per Solana docs): mint with `ConfidentialTransferMint + autoApproveNewAccounts + auditor key` → create accounts → mint-to → deposit → apply-pending → proof-context accounts (equality/ciphertext-validity/range) → transfer; v1 single-tx path with multi-tx fallback; CU budget measured, not guessed.
- Context7-first development rule (MANDATORY): before writing program code for any of Todos 3-10 and 12, the worker MUST query Context7 (`/websites/anchor-lang`, `/websites/solana`) for the exact constructs involved and record the doc URL once per todo in its evidence (a single `Docs:` trailer on the todo's main commit suffices — keep lookups lightweight so D2-D4 never slip). If Context7 is unreachable, websearch fallback with URL logged. Never code security-critical constraints from memory. Todo 1 records the baseline lookups; each later todo records its own.
- Money/window defaults are demo-tuned values for judging legibility, not production treasury policy — ARCHITECTURE.md (Todo 16) says so explicitly.
